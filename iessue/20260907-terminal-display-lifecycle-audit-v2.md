4 个 subagent 分别检查渲染、生命周期、回放连接、周期刷新；复用第 5 个反方 agent 复核。没有连接用户 PTY、重启服务或修改业务代码。前端 94 项测试通过，不能替代实际故障现场证据。

## 优先处理

| 优先级 | 发现与触发条件 | 证据与最小建议 |
|---|---|---|
| 1 | 不同轮次的大批输出可能让终端反复短暂空白 | `terminal/resume.ts:71-94,158` 累计 JS 字符串长度达到 256×1024 后 freeze，`terminal/xtermEngine.ts:216-218` 用 visibility:hidden 隐藏整个终端。普通实时输出不要隐藏画面，回放另外显示恢复状态。 |
| 1 | 有存活会话，但 selectedId 无效时全部终端隐藏 | `store/state.ts:36-38` hydrate 不校验；`components/TerminalPane.tsx:157-166` 有会话却没有任何 active。两个 agent 用实际 reducer 复现 openCount=1、visibleCount=0。统一校验选择状态并在视图兜底。 |
| 2 | 本地缓存写入失败可能卸载整个工作台 | `store.ts:127-140` 的 localStorage.setItem 未捕获异常，`main.tsx:15-18` 外层 ErrorBoundary 可替换工作台。捕获非关键缓存写入失败。此情况应呈现全局错误文本，不应混同仅终端空白。 |

反方修正：输出风暴的阈值是 JS string.length，不是实际 UTF-8 字节。连续一轮输出超过 1.2 秒后会保持可见，不是每 1.2 秒再次隐藏；只有风暴结束后下一轮突发或回放才可能再隐藏。机制确定存在，但没有证明用户过去的每次空白都由它引起。

## 次要缺陷与恢复边界

- IME：`terminal/ime.ts:165,175,200` 在组词开始锁定光标，面板缩小后不限制旧列号。agent 用假 DOM 调实际 attachTuiIme 复现 100 列第 90 列缩到 40 列，锚点 left=900px 超出 400px 终端。建议对锁定坐标按最新行列约束。
- 查找：`components/TerminalPane.tsx:28-53,70-72,97` 关闭按钮未统一 clearSearch，切会话后查询文字/未找到状态与旧终端高亮未同步。统一关闭和句柄切换处理。
- 提示：`components/TermView.tsx:47-54` 的 6 秒计时在切走/断线时被清理，切回重新计时；localStorage 修复了刷新，但已挂载视图不重读。按首次显示 deadline 处理即可。
- 初始化：`terminal/sessionController.ts:133-200` try/catch 仅包等待布局和 mount，后续 connect/观察器初始化抛错未统一处理。假依赖抛错复现 unhandledRejection；真实生产异常来源尚未确认。
- 快照：`terminal/sessionController.ts:89-90,233-248` pagehide 依赖异步 snapshot，隐藏时不提前保存，队列未清空时同步 snapshotNow 可返回 null。可能只能依赖旧快照与服务端有界回放，并不等于必然丢失输出。
- 半开连接：前后端均未见 WS 存活心跳，connection.isAlive 主要依赖 readyState。网络异常未发 close 时可能显示连接正常却无输出；这是条件性韧性缺口，不能用空闲无输出来判断断线，也不能据此解释画面自行清空。

## 周期表

| 周期或事件 | 行为 | 是否重建终端 |
|---|---|---|
| 4 秒 | 拉取 workspace，普通端 patchLive、稳定端 hydrate | 稳定 ID 下不重挂载；稳定端无变化也可能重渲染和写缓存 |
| 2 秒 | 检查输出解析是否超过 10 秒 | 只更新诊断提示，不重启 |
| 5 秒 | 活动检测，检查是否静默 30 秒 | 通知、声音、标题，不改终端 DOM |
| 1 秒，诊断面板打开时 | 读取诊断数据 | 仅诊断 UI |
| 容器变化后 50ms 防抖 | fit、满足条件后同步 PTY 尺寸 | 不重建，但隐藏会话也可能执行本地 fit |
| focus / online / visibility | fit、repaint、必要时重连 | 相邻事件可能重复重绘，需合并而非假定数据轮询重建 |
| 主题变化 | 修改 renderer 选项 | 不新建实例 |
| 首次等布局最长 400ms | 等待容器尺寸后挂载 | 初次挂载，超时后可由 ResizeObserver 补 fit |
| 源码 HMR | 可能重跑 React effect | 可能重建，属于开发更新而非固定周期 |

## 首批修复

- 删除实时输出风暴触发 visibility:hidden 的逻辑及安静期定时器。保留输出合并、解析后提交游标；全量 replay 的短暂隐藏与 1.2 秒上限保持，catchup 不隐藏。
- reducer 在状态转换后校验 selectedId，保留有效目标，无效时尝试前次有效选中再回落首个打开会话；本地加载复用校验。稳定 API 过滤失效 metadata.selectedId，TerminalPane 增加显示兜底。
- 本地工作区缓存写入捕获配额/权限异常，不影响内存与服务端状态；稳定模式不再写开发工作区缓存。
- 新增无效/已关闭选择、删除最后会话、无变化轮询对象稳定、缓存失败、大批实时输出与 catchup 不隐藏、全量 replay 隐藏上限回归。前端 95 项测试通过，包边界检查通过。

本批没有重启服务或用户 PTY；IME、搜索、提示计时、初始化及心跳的次要问题仍待后续处理。

## 第三批修复：连接探测和关页快照

- 业务网关与 core hello 新增可选 heartbeat:1；协议支持严格 nonce 校验的 ping/pong。探测消息仅网关应答，不写入 PTY，不改变输入/尺寸/daemon 协议。
- 前端仅在已协商且回放解析完成后启动探测：每 15 秒一次，10 秒无匹配应答时替换 WebSocket，不等待半开旧连接完成 close；使用现有已解析游标恢复，不强迫全量重放。旧后端未声明能力时不发送新消息。
- 后台页面暂停探测，后台/系统休眠导致超时回调明显延迟时重新安排探测；旧连接应答不会影响新连接，退出/销毁清除定时器。
- 页面隐藏提前保存：已解析则同步捕获，尚有输出则合并为一个异步快照请求。pagehide 只尝试同步捕获，不把未解析输出当成已恢复游标；来不及解析时仍依赖旧快照及服务端有界回放，不承诺零历史损失。
