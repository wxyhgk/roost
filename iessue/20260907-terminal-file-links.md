# 终端文件链接打磨

## 已修复

- xterm provider 使用 1-based 行号，buffer.getLine 使用 0-based；原实现读取了下一行。
- 按真实 buffer cell 映射 UTF-16 匹配区间，处理中文宽字符、组合字符与软折行，链接末尾使用包含式格坐标。扫描限于最多 65 行，过长逻辑行跳过。
- 增加中文路径、带引号的空格路径和常见前端/图片扩展名；URL 不当作文件。
- 悬停显示路径、行号及修饰键提示；macOS 使用 Command + 点击，其他平台使用 Ctrl + 点击。鼠标移动超过 4px 的拖动不打开；已有选区不阻止打开。
- 文件视图未挂载时暂存最新请求，外壳展开文件面板，挂载后按会话消费一次。
- 无法归属当前工作目录时显示错误，不再静默忽略。
- 重复点击同一个文件不再以 nonce 改变编辑器 key；行号导航在现有编辑器中执行，避免重建导致草稿丢失。

## 验证与边界

前端 94 项测试通过，包括行号坐标、中文/组合字符、软折行、引号路径、URL 排除与延迟消费；类型检查和包边界检查通过。未用用户运行中的 PTY 做鼠标验收。

仍按当前会话 cwd 解析，不自动搜索全盘、不推断历史输出时的 cwd；根目录外路径与 ~/ 路径仍可能无法打开，并显示原因。未加入文件存在性悬停查询；本轮支持行号定位，暂未增加列号定位。

## 点击失效回归修正

用户反馈所有文件都打不开、只有 URL 可用。浏览器隔离页复现普通点击无回调；移除文件独有的修饰键要求和全局 hasSelection 拦截，改为判断本次鼠标手势。实际点击确认 `.github/workflows/release-desktop.yml:5` 与 `src/app.ts:12` 分别传出正确请求。RetainPDF 工作目录下 release-desktop.yml 经 5173 文件 API 读取返回 HTTP 200。13 项文件链接测试及前端类型检查通过；没有操作用户 PTY。测试页：`frontend/tests/browser/terminal-file-links.html`。

后续按用户偏好恢复 Command / Ctrl + 点击，保留本次手势拖动判断，不恢复全局 hasSelection 拦截。上面的普通点击验证属于中间版本。
