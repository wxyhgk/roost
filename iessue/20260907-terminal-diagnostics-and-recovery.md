# 终端白屏诊断与局部恢复

## 范围与判断

本轮处理当前 5173 前端。历史白屏没有在现场保留完整证据，不能断言都属于同一根因。原先已有回放冻结最长 1200ms 的保护和 WebGL 丢失降级，但缺少可查看的阶段/解析进度，以及不刷新整个页面的恢复入口。

## 改动

- 每个活动终端右上角增加“诊断 / 恢复”，显示布局/连接/握手/回放/可交互阶段、渲染器、上下文丢失次数、实际尺寸、行列数、已解析与已接收游标、排队数量、冻结状态。
- 保留最近 40 个生命周期事件；复制诊断包含当前状态和手动重载前的状态，不包含命令、输出正文、工作目录、URL 或快照正文。记录在内存中，不进行逐帧持久化。
- “恢复画面”：保留 xterm 缓冲区，切换 DOM 渲染并重绘。显式操作后重新适配选中终端尺寸，不创建/结束/重启 Shell。
- “重新加载视图”：只销毁当前浏览器视图与连接，重新挂载现有控制器，跳过本地旧快照并重新接入原 session。只恢复服务端保留范围内的历史，不承诺无限历史；旧连接未发送的排队输入不会转移到新视图。
- 正在等待解析超过 10 秒且窗格活动、页面可见时提示检查。静默但没有待解析输出不视为故障，不根据输出间隔自动重启 Shell。
- 握手 12 秒未收到基线帧时重试连接；已收到 replay 但解析慢不触发该网络重连定时器，避免反复回放。
- 回到窗口时刷新当前终端渲染；后台/非活动窗格不从常规 fit 发送尺寸通知。WebGL 部分加载失败也清理 addon。正常唤醒重绘不解除回放冻结，手动恢复可以解除。
- dispose 会释放尚未完成的写入等待，旧解析回调不会推进已销毁视图的游标或操作新视图。

## 验证

- frontend TypeScript 检查、75 项前端测试、6 项独立工作台测试、工作区依赖边界、git diff 空白检查通过。
- 新增测试覆盖诊断容量与副本隔离、空闲/隐藏窗格误报排除、解析卡住后的释放、局部重绘不重启/重连、握手超时及慢解析边界。
- 完整前端构建通过。原有 3dmol eval 与大 bundle 提示仍存在，本轮没有把它们当作终端白屏的根因。
- `frontend/tests/browser/terminal-recovery.html` 在现有 Vite 上提供可重复的本地渲染故障注入。模拟 visibility 隐藏后恢复 DOM，RENDER_RECOVERY_OK 保留；模拟 WebGL context loss 后回到 DOM，contextLosses 为 1，缓冲区保留。
- 真实独立测试 core 8791 + 页面 8790：点击恢复与重新加载视图后 `_VIEW_RECOVERY_OK_` 恢复，仍能输入并显示 AFTER_VIEW_RELOAD_OK。PID 始终 19283，instanceId 始终 62bb6393-2be8-4ce3-9ed0-118dcb254bb0。
- 正式 8789 固定版本仍是 104539e7c90253cf，未执行安装/activate。真实终端 PID 15347、16083、16439 保留。测试端口和临时 daemon 在验收后清理。

## 使用

在 5173 遇到空白时先打开“诊断 / 恢复”，复制诊断，再点“恢复画面”；如果连接或解析卡住，可用“重新加载视图”。新增诊断用于给下一次现场故障提供证据，本轮不宣称所有白屏情形均已消除。
