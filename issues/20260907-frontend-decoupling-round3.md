# 第三轮：终端会话控制器与空白画面风险

日期：2026-09-07。承接 [第二轮](20260907-frontend-decoupling-round2.md)。

## 用户报告与判断边界

用户报告终端偶尔空白，刷新页面后恢复。截图中会话栏、文件树正常，底栏显示“已连接”；日志含 React DevTools 提示和 `/api/file?...session.py` 的 404。

- React DevTools 是开发提示。
- `/api/file` 是文件预览请求，FilesView 独立捕获预览错误；该 404 不能直接解释终端整体空白。
- 已在代码中确认一个可造成长时间空白的机制：重放/输出风暴通过 `visibility: hidden` 隐藏画面，风暴等待输出安静并排空解析队列后才解除；持续输出可能使隐藏一直保持。
- 未采到用户故障当时的 DOM visibility、WebGL 状态和解析队列，因此不把这一机制认定为截图中故障的唯一根因。

## 已实施

1. `sessionController.ts` 接管挂载等待、连接、重放、图片粘贴有效期、快照、尺寸监听、退出重启和清理；通过 SessionDependencies 注入浏览器/网络/引擎能力，不依赖 React。
2. `sessionRuntime.ts` 装配浏览器适配；`useTerminal` 缩为挂载控制器、接收状态、更新主题/活跃状态和转发操作。
3. 每次挂载取得会话所有权。旧控制器不能发送输入、更新会话状态/cwd/cli、发布快照或在清理时删除新控制器的注册项。清理幂等，等待尺寸时卸载会取消观察与定时器。
4. 文件链接由引擎回调上交运行时，携带来源 sessionId；FilesView 按 sessionId 订阅，切换会话后旧来源链接不会按新会话 cwd 解析。
5. 冻结画面加入默认 1200ms 的解除隐藏保护，持续输出或慢解析不再无限隐藏；保护触发后解析和批处理继续进行，不丢弃输出。实际触发时刻仍受浏览器定时器调度影响。
6. 销毁重放控制器时解除隐藏；无有效容器尺寸时保留现有行列；尺寸适配、返回可见页面与 WebGL context loss 回退时请求重绘。
7. 依赖检查增加 sessionController 不得引入 React 的规则。
