# 直接使用现有前端发布稳定版

用户纠正了“再做一套相似界面”的理解，明确要求直接使用现有前端。此决策取代首版禁止导入 App/Shell/CSS 的限制；独立安装、固定产物和终端直连基座仍保留。

## 实现

- stable.html 读取部署配置后直接加载现有 main.tsx/App/Shell，全套现有组件和样式进入同一发布产物；删掉原独立工作台的 HTML、main.ts 和 CSS。
- 构建运行 Vite，运行时只使用已打包本地资源，固定版本服务器支持分块脚本和本地图标，不加载 Google Fonts/CDN。
- 稳定模式发现存活会话走 core，异步附加业务元数据；业务断开不会阻塞发现和切换终端。
- 原有 connection 增加 core JSON 协议模式，禁用输入排队、快照上传和颜色响应；原有 resume 继续负责完整解析游标，尺寸通知增加主动使用判断。
- 同源业务 API 代理保留文件、笔记等现有功能；业务错误保留在所属区域。右侧面板和命令面板增加局部错误边界。
- 安装器支持完整前端多资源清单，校验 hash、路径和空 cwd 启动，候选验收之前不切换 current。

## 验收证据

- frontend 类型检查、70 项前端测试通过；工作台 6 项测试通过，真实 core 合同测试已改为使用现有 frontend connection/resume。
- 候选页面 8790 连接临时 core 8791，业务地址指向未监听的 8792。文件与笔记显示不可用，但终端可输入并回显 SHARED_FRONTEND_OK。
- 切换原版深浅主题、文件/笔记区域后终端保留。刷新页面后回放恢复 SHARED_FRONTEND_OK；测试终端 PID 50352、50353 和 instanceId 不变。
- 工作区边界检查、diff 空白检查通过。未停止用户 Vite、业务后端或真实 daemon，也未向用户终端输入测试命令。

业务功能仍需要 8787；稳定终端仅依赖 8788 与 daemon。没有宣称共享 Shell 的任意运行时异常都可以隔离。
