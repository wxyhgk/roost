# 一个终端承载的是一串原生会话，不是一个

日期：2026-09-09。起因是只读同步面板上线后的**第一次真实使用**就卡死了。
本文记录根因、已落地的最小修复，以及建议由后端继续推进的两层。

后续 [P0 耐久历史](ai-history-implementation.md) 和 [P1 安全自动换绑](ai-auto-rebind-implementation.md) 已完成；本文下方是原问题与方案记录，当前行为以实现说明为准。

## 现场

真实数据（omp v18.1.11，日常环境）：

- 绑定钉在 `01a083a1-3b0a-741c-b46b-a03c22e2a96c`，agent 随后自报 `01a080cf-a6aa-70a4-ad8c-83cfdaee63fa`
- `terminalInstanceId` 前后一致 —— **同一个 PTY，不是终端被替换**
- 绑定被置为 `offline`，`sync.lastError = "needs_rebind"`，`hasMessages: false`，事件只有两条状态标记
- 面板永久停在「连接或身份未确认」，本轮没有换绑入口，无法自愈

关键证据在磁盘上：

- `01a080cf` 存在：`~/.omp/agent/sessions/-Code-diy_ai_coding_web/2026-09-08T11-38-07-402Z_01a080cf-….jsonl`（前一天）
- `01a083a1` **不存在任何文件**

即：omp 启动时先用一个**临时 ID** 发了 `session_start`，我们据此建立绑定；用户随后恢复了昨天那段对话，
后续事件换成了旧会话的 ID。按 UUIDv7 时间序，`01a080cf` 也确实比 `01a083a1` 更早。

## 根因不是策略，是模型

当前模型假设「一个终端 ↔ 一个原生会话」终身 1:1。事实是**一个终端在时间上承载的是一串原生会话**：
启动一个、恢复昨天那个、`/new` 再开一个、再切回去。把这种正常切换判成异常，
等于把最常见的工作流（续昨天的活）判成故障。

要防的东西只有一个，而且是对的：**绝不能把两段不同的对话拼成一段**。
但防拼接的机制早就有了 —— `rebind` 会开新 generation、清空展示缓存、从新会话的日志边界重新补收，
结构上就拼不起来。

### 人工确认在这里没有增加安全性

`server.ts` 的 rebind 路由自己的校验是：读当前 PTY 的来源日志、找出最新的 `nativeSessionId`、
要求它等于请求的那个。**这是纯机器可验证的**，人点那一下不提供任何机器拿不到的信息，
只是把一个可自动完成的动作变成了一个卡死的状态。

正确的分工是：**能自证时自动推进，无法自证时才问人。**

## 已落地（第一层）

`backend/src/ai-agent-source.ts`：身份改换时，若当前绑定**还没有任何消息正文**
（`bridge.source(id).hasMessages === false`），自动挪到新身份（`adopt()` → `bridge.rebind`，开新 generation），
而不是下线。

依据很硬：**零消息时不存在可拼接的东西**，拒绝改换纯属自伤。而 agent 启动时先发的那个
`session_id` 往往是临时的（没有内容就不会落盘），在它上面把身份钉死本身就太早。

已同步过正文时保持原行为：下线 + `needs_rebind`，因为跟过去会丢掉已经可见的历史，那必须由人确认。

同批修的两处：

- `createAiAgentSource` 新增 `onRebound` 回调，`server.ts` 用它断开旧的 WebSocket。
  **这是必须的**：`bridge.rebind` 会清空订阅者集合，不断开的话那条流会永远静默，客户端还以为自己在线。
- 实时事件路径原本把 `processAgent` 返回的 `"needs_rebind"` 丢掉了（只有补收路径会记）。
  结果是绑定悄悄下线而 `sync.lastError` 为 null，界面说不出原因。现在两条路径都记录。

回归测试：`backend/tests/ai-agent-source.test.ts` 最后一条，覆盖「空绑定自动跟随并开新 generation」
与「有正文时停下且不产生新一代」两侧。

## 建议后端继续推进

### 第二层：可自证时自动换绑

身份变更且**已有正文**时，若 daemon 支持补收、且来源日志能证明新 ID 是当前 PTY 实例的最新身份
（与 rebind 路由现有的那段扫描同一套判定），就自动 `rebind` 并发一条边界标记，而不是下线。
把 generation 变成一等公民：一个终端 = 一串有序 generation。

只在**机器证不了**时才保留 `needs_rebind`：

- daemon 不支持补收（旧 owner）
- 来源日志在切换点上有缺口，无法定序
- 同一窗口内出现多个候选身份，无法判定哪个是当前的

### 第三层：让切换不破坏历史

`rebind` 目前明确「不归档旧 generation 的展示缓存」。改成归档（沿用现有 4096 条 / 8 MiB 上限，
再加一个「保留最近 N 代」），这样 A→B→A 来回切不丢东西，也依然不拼接。
之后面板可以提供「这个终端里的上一段对话」。

### 前端要改什么：几乎不用改

自动换绑后不必再用 1008 关连接，**直接在同一条 socket 上推一帧新的 `ai-session-snapshot` 即可**——
前端归约器收到快照就是整份替换，天然不拼接，已有测试守着
（`frontend/tests/ai-session.test.ts`「跨 generation 的帧不拼接」）。
前端只需加一个「已切换到另一段对话」的边界提示。

在第二层落地之前，前端仍需要一个**人工换绑入口**来处理「已有正文」那一侧，
否则那种情况依然只能靠删掉会话重来。
