# 03 移动端操作方案：源码证据、实施依赖与验收

> 2026-09-09 对照当前工作区与 `research/third-party/warp` 修订。
> 本文是源码审阅后的设计方案；尚未实现，也未通过手机或桌面浏览器验收。
> 下文源码路径均相对仓库根目录，符号优先于可能随编辑变化的行号。

## 1. 能借鉴什么，不能据此声称什么

Warp 的原生 GUI 与我们的 React + xterm.js 在输入、渲染和坐标系统上不同。以下证据支持架构借鉴，不证明 Warp 已有适用于本项目的手机交互。

| 已核对的 Warp 源码 | 能支持的判断 | 移植边界 |
| --- | --- | --- |
| `research/third-party/warp/crates/warp_terminal/src/model/selection.rs`：`Anchor`、`ExpandedSelectionRange`、`Selection::new/update/to_range` | 选区由网格坐标、起止点和选择类型建模，存在行选择与语义选择 | 不提供浏览器 DOM Range 或 xterm 触屏适配 |
| `research/third-party/warp/app/src/search/command_palette/data_sources.rs`：`DataSourceStore::new/reset_search_mixer` | 命令动作、会话导航、新建会话等作为不同数据源组合 | 我方不能仅改资源搜索弹窗样式就声称具有统一命令系统 |
| `research/third-party/warp/app/src/search/command_palette/view.rs`：`Action::Close`、`View::close` | 命令面板有自己的关闭、重置和关闭事件 | 不支持“取消一次关闭所有界面并中断终端”的设计 |

Emacs 的 mark/point、kill-ring、命名命令可以启发产品，但本次未以 Emacs 源码证明这些实现，也没有在上述 Warp 证据中确认完整 kill-ring。下面的“两点选择”“剪贴历史”“底部操作条”“分层取消”均是我方独立设计建议，不标注为 Warp 已验证方案。剪贴历史首版也不承诺 Emacs 式 yank-pop：替换已发送至 PTY 的文本需要另一套输入编辑模型。

## 2. 我方已有能力与真实缺口

| 当前源码 | 已有能力 | 本次需要补齐 |
| --- | --- | --- |
| `frontend/src/terminal/types.ts`：`TermHandle`；`terminal/xtermEngine.ts`：`getSelection/onSelectionChange` | 获取终端选中文本、订阅变化；引擎有 WebGL 渲染路径 | 没有公开的选择范围、清除选区、触点到网格坐标接口 |
| `frontend/src/terminal/handles.ts`：`subscribeSelection` | 句柄重建时重新订阅选区事件 | 复用该生命周期，不另建只在首次挂载时订阅的链路 |
| `frontend/src/components/SelectionSaveBar.tsx`：`useTerminalSelection` | 已订阅选区变化，但只在选区为空时隐藏；`readSelection` 用鼠标坐标打开操作条 | 不能再写成“完全没有使用选区订阅”；还缺触屏创建选区和非鼠标操作条定位 |
| `frontend/src/components/TermView.tsx`：`onMouseUp` | 鼠标释放触发读取选区 | 不能依赖合成鼠标事件完成手机长按选择 |
| `frontend/src/clipboard.ts`：`writeClipboard/legacyCopy` | Clipboard API 失败时尝试旧复制路径，返回成功与否 | 缺应用内剪贴历史；已有 fallback 不能等同于所有手机都复制成功 |
| `frontend/src/components/CommandPalette.tsx`：`sections/jump` | 会话、文件、笔记、片段搜索；空查询按等待处理和最近输出排列会话；关闭后处理焦点 | 缺统一动作注册和窄屏、软键盘布局 |
| `frontend/src/App.tsx`：`pointerOptions`；`components/SessionRow.tsx`、`ProjectGroup.tsx` | PointerSensor 距离阈值 8，列表行挂拖拽监听并使用 `touch-none` | 滑动与拖拽需分开；不能只替换 CSS |
| `frontend/src/index.css`：`.session-toolbar`；`components/Shell.tsx`：`autoSaveId` | 工具条支持 hover、键盘焦点与显式展开；面板布局持久化 | 仍需常驻触屏入口；紧凑布局不能覆盖桌面尺寸偏好 |

## 3. 实施顺序与依赖

推荐 **A 触屏基础 → B 终端选择与复制 → C 命令入口与取消 → D 剪贴历史**。A 的视口和焦点约定由 B/C 共用；D 依赖 B 的明确复制入口。每阶段先通过自己的验收再推进，不用“几十行”估算工作量。

### A. 触屏基础与可见视口

实施位置：`App.tsx`、`SessionRow.tsx`、`ProjectGroup.tsx`、`Shell.tsx`、共用按钮和样式。

- 布局按可用宽度判断紧凑模式；`pointer: coarse`、`hover: none` 用于操作尺寸和悬停替代。实际手势按事件的 `pointerType` 区分。粗指针不等于手机，触屏笔记本和平板外接鼠标不能被强制锁进一种模式。
- 将排序监听及 activator 属性移到明确的拖拽手柄；普通行区域允许纵向滚动。仅手柄保留需要的 `touch-action` 限制，避免整行 `touch-none`。若采用独立鼠标/触屏 sensor，应避免 PointerSensor 与 TouchSensor 重复处理同一输入。
- 长按延迟和移动容差通过设备验收决定，不能把 `delay:150` 写成通用正确值。手柄排序同时保留键盘或菜单移动入口；行内按钮不得启动拖拽或误选会话。
- 无悬停时常显菜单入口；按钮触摸目标以至少 44 CSS px 为设计目标，不要求把每个动作全展开挤在一行。
- 紧凑布局用抽屉打开会话和文件面板，保留返回终端入口。独立保存紧凑布局偏好；切断点不能销毁会话或反复重建终端。
- 定义统一可见视口适配：优先动态视口高度，必要时监听 `visualViewport` 的 resize/scroll，结合高度与偏移放置底部层；无此 API 时有基础 CSS 回退。避免对浏览器已处理的缩放/键盘位移重复补偿。
- 底部操作条考虑 `env(safe-area-inset-bottom)`，终端与抽屉为操作条留空间。软键盘升降、地址栏变化和横竖屏切换后，输入框及主要按钮都必须位于可见区域。
- “键盘”按钮在用户点击链路内聚焦终端输入。浏览器是否显示软键盘必须实测；不能把 `focus()` 当作跨浏览器键盘开关。关闭弹层恢复焦点时区分浏览状态与正在输入，避免复制后意外弹键盘。

### B. 终端选区：先建立模型，再显示操作条

实施位置：`terminal/types.ts`、`terminal/xtermEngine.ts`、`terminal/handles.ts`、`SelectionSaveBar.tsx`、`TermView.tsx`。

1. 审核安装版本的 xterm 公共 API，再通过 `TermHandle` 封装所需选择、清除、范围和视口能力。视图层不要直接读取 xterm 私有 `_core` 字段；如公共接口不足，先完成坐标适配验证并记录版本依赖。
2. **不能用 `window.getSelection().getRangeAt(0)` 当终端选区几何。** WebGL/canvas 下文字和浏览器 DOM 选区不等价。复制正文来自 xterm 的选择模型；操作条首版固定在可见视口底部，不依赖 DOM Range。
3. **`onSelectionChange` 只报告变化，不创造触屏选区。** 新增明确“选择”模式：进入后点起点、点终点形成范围，提供按行扩展/收缩和取消。默认浏览模式仍可滚动和点击链接，不让所有触点都成为选区。
4. 触点转换必须覆盖终端内容区域偏移、单元格宽高、滚动位置、缓冲区行号和边界裁剪。中文宽字符、组合字符、emoji、自动换行、反向选择都要验证；明确“整行”是屏幕行还是含折行的逻辑行，按钮文案与实现一致。
5. 长按可在两点选择稳定后作为快捷入口：状态机区分 pending/selecting/scrolling；移动超过容差、`pointercancel`、多指操作、切会话都取消待触发长按。不要在 pending 阶段吞掉普通滚动；选择模式才捕获需要的指针，退出时释放。
6. 同步选区事件用于更新/隐藏操作条；复用 `subscribeSelection` 跟随句柄替换。resize/reflow、历史裁剪、输出更新、普通/备用缓冲区切换时，确保范围仍有效，否则明确取消选区，不能复制到另一段文本。
7. 操作条提供复制、存笔记/片段/文件、取消，保留现有保存能力。点击按钮时保留待操作文本，避免焦点变化清掉选区后复制空字符串。
8. 复制保留选区原文，不沿用 `readSelection` 当前的尾部空白裁剪；笔记标题等展示性处理与复制正文分离。调用 `writeClipboard` 后显示真实成功/失败结果，失败保留选区便于重试。

### C. 命令入口与分层取消

实施位置：`CommandPalette.tsx`、`CommandPalette/search.ts`、`Shell.tsx`；新增命令注册与可关闭层的共享约定。

- 定义命令项的稳定 ID、标题/检索词、可用条件和执行函数；先接新建会话、切会话、打开文件面板、设置、进入选择模式。按钮、快捷键、命令面板共用动作，避免移动端维护第二套行为。
- 保留现有资源搜索与空查询会话排序；命令动作作为新增类别。`matchItem/matchFile` 可以复用作匹配工具，不能替代命令注册、可用性判断及执行。
- 紧凑模式下命令面板使用适配可见视口的底部层，结果区可滚动；触屏入口可见。五个固定按钮只是候选布局，按窄屏空间合并低频入口。
- 取消按最上层优先、一次消费一层：关闭最上层菜单/弹层 → 退出当前选择模式 → 恢复合理焦点。底部关闭按钮与应用层 Escape 共用此规则，不建立无差别 `cancelAll()`。
- 图片确认、正在上传、未保存编辑各有生命周期。仅在对应层处理关闭/取消；不得因为关闭命令面板而调用其他层的 `cancelImage` 或丢掉编辑。
- 不默认全局拦截 `Ctrl+G`、`Ctrl+C`、Escape 并发送中断。终端本身拥有焦点且没有应用层消费时，保持原输入语义；“中断 CLI”若需要，提供明确独立动作。
- 关闭后把焦点交给实际目标；导航到文件时不要抢回终端。输入法组合期间不把候选确认当执行命令；弹层支持焦点约束及返回触发入口。

### D. 应用内剪贴历史

实施位置：`clipboard.ts` 及经过明确接入的复制调用点；新增内存 store 与历史抽屉。

- 首版只记录明确由用户触发的应用复制，且区分系统复制成功与失败。不在选区变化时入栈，不轮询系统剪贴板，也不把终端输出或程序发起的剪贴板写入自动收录。
- 审核 xterm 原生复制及 `ClipboardAddon` 路径后决定如何接入；未接入的快捷键路径不声称已覆盖。剪贴历史应说明它是应用内记录，不是系统历史。
- 建议内存最多 20 条，并设总容量上限、去重和清空入口；页面刷新后清空，不新增跨设备同步。超限按完整条目淘汰；单条太大时复制完整内容并提示未收录，**不得静默截断成 10KB 后让用户以为拿到全文**。
- 点历史项再次执行明确复制并报告结果，默认不写入 PTY、不自动发送 Enter。预览可省略，但复制必须取完整原文；“插入终端”若后续增加，作为另一个显式动作并遵守现有输入路径。
- 不承诺非安全上下文的旧复制方法必定有效。真实失败时提供保留全文的可选择文本界面，让用户继续操作；历史记录和系统剪贴板状态不可混淆。

## 4. 验收与完成标准

以下均为待执行验收，不是本次调研结果。至少记录设备、系统/浏览器版本、访问协议、复现步骤与截图或录屏；桌面设备模拟不能替代真实手机。

| 范围 | 必须覆盖 | 通过条件 |
| --- | --- | --- |
| 触屏列表 | 真机纵向滑动、点击菜单、手柄排序、取消拖拽 | 无误拖、无误点击；会话增删改与排序有可操作入口 |
| 终端选区 | iPhone Safari 与 Android Chrome；中文、英文、emoji、链接、折行、反向与跨屏选择 | 内容准确，滚动不误入选择，按钮不会清空待复制文本 |
| 动态终端 | 输出持续到来、resize、历史裁剪、切会话、缓冲区切换 | 选区保持正确或明确取消，不错拷另一会话/另一行 |
| 可见区域 | 软键盘开关、中文输入法、横竖屏、地址栏收缩、安全区、页面缩放 | 终端输入和底部操作可见，不出现双重位移或布局振荡 |
| 命令/取消 | 触屏新建与切会话、打开文件；多层弹窗、图片确认、终端前台程序 | 不依赖快捷键；一次仅关闭目标层，不误中断 CLI、不丢其他状态 |
| 剪贴历史 | 连续三次复制、复制失败、重复内容、超大内容、容量淘汰 | 顺序和正文准确；失败可重试，超限行为可见，无静默截断 |
| 混合输入与回归 | 桌面鼠标/键盘、触屏笔记本、平板外接键盘鼠标 | 原选区、快捷键、拖拽与桌面面板偏好保持可用 |

实施时对坐标换算、选区状态机、取消事件归属和历史容量边界做针对性测试；视觉、滚动及软键盘结论以真实浏览器验收为准。文档修订本身不需要运行 Warp 构建或把未执行的产品测试记为通过。
