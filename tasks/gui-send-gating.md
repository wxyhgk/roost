# GUI 往 CLI 发消息：闸门该怎么设（四路讨论 + 两轮互评的裁决）

2026-09-15。四个 agent 分头出方案，然后把彼此结论互相喂回去挑刺，两家各自改了结论。
这份是裁决，不是四份报告的拼贴。**标 [实测]** 的是在本机真跑出来的。

---

## 一、出发点错了：问题不是那张表

起点是 Warp 的「按 agent 的投递策略小表」（claude 要"文本→50ms→回车"，codex 要
bracketed paste），担心它随版本失效。四路查完，这个担心对 roost **基本不成立**：

- **roost 的表只有一行。** qwen 写 input.jsonl、codex 走控制 socket、opencode 走本机
  HTTP——**都不敲键盘**。只有 claude 还在敲（`ai-command-owner.ts:134`）。
- **[实测]** claude 2.1.273 上，单次写入 `ESC[200~ 正文 ESC[201~\r`（正文和回车同一个
  buffer）**提交成功**；纯文本 `正文\r` 也成功。**Warp 表里「Claude = DelayedEnter」那条
  在 2.1.273 上已经过期。**
- **[实测]** 四个 CLI 全都开了 DECSET 2004，而 Warp 给它们分了三种策略 → **那张表不是从
  任何可观测量推出来的**，是口口相传。

> 照抄别人的表，会照抄进一个在本机已被证伪的条目。**别人的表不该是权威，自己的账本才是。**

**真正挡住我们的是版本钉子**（`ai-command-owner.ts:49` 精确要求 2.1.266，本机是 2.1.273），
不是那张表。

## 二、最重要的发现：两条正交的失效轴，我们只有一道闸

| 轴 | 问的是什么 | 今天谁在挡 |
| --- | --- | --- |
| **收件人错** | 这些字节会送到谁手里？（claude 还是它 fork 出来的 vim / less） | **只有屏幕正则，而且是意外的代理** |
| **agent 状态错** | CLI 内部在干什么？（idle / 忙 / 弹着权限框） | 屏幕正则 + 部分事件 |

### 收件人错这条轴上有一个现存的洞

`cliForPid`（`packages/terminal-runtime/src/processes.ts:49-74`）在**整棵进程子树里深度
优先找 CLI，命中即返回，不判断前台**；`index.ts:251` 用它填 `session.cli`。

所以 claude 起了 `vim`（`git commit`）或 `less` 时，`live.cli` **仍然是 `'claude'`**，
`unsupported_cli` 那道判断过不了滤。

**今天唯一挡住「把正文粘进 vim」的，正是那条我们打算退掉的正则**——vim 的画面认不出
`❯` 和上下边框，返回 `screen_unknown`。而它作为前台判断是脆的：locale 变了、或撞上
「vim 刚启动屏幕还没重绘」的窗口，就会漏。

### 这条轴上，拆写完全帮不上忙

讨论中一度很受欢迎的「把落字和按回车拆成两次写」，对 vim 这种情况**一点用都没有**：
vim 的 normal mode 下**正文本身就是一串命令**（`d`、`:`、`!`、`ZZ`…）。**危险全在正文里，
不在那个 `\r` 里。**

也不能靠 bracketed paste 标记兜底：vim 8+ 当字面插入、`less` 直接忽略、别的程序又不同
——**那正好又是一张随版本失效的行为表**。

**正确的闸是 `tpgid`**：PTY 的前台进程组是不是 CLI 的进程组。这不是又一个启发式——
**`tpgid` 就是内核对「这些字节会送给谁」的答案**，正则只是从像素去猜这个答案。

## 三、一条硬约束：「退掉读屏」和「自动按回车」不能同时成立

**[实测]** 在 codex 停在登录界面时，一次带 `\r` 的盲探测**真的触发了一条 OAuth 授权流程**。

那个界面**既不产生 agent 事件，也不是我们意义上的 dialog**。所以一套「不看屏幕、靠事件
判断」的闸门会**原样放行**那个回车。

> 一个自己不看屏幕、又肯盲按回车的系统，没有任何机制能防住这一类。

世界上存在「既不是 agent 对话框、又不产生任何事件」的屏幕，登录界面就是一个。所以：

- 要么看屏幕（那就得接受版本钉子）；
- 要么不看屏幕，但**绝不主动按回车**——把字留在输入框，让人自己按。

**中间没有安全地带。**

同一条实测还**一票否决了盲探针**（原本被当作"无害的自测手段"）：

> 探针的危险性和真消息完全相同，因为**「无害」是相对于收件人定义的，而探针存在的理由
> 恰恰是我们不知道收件人是谁**。

## 四、被撤回的方案（两家自己撤的，记下来免得再想一遍）

**自动重按回车的阶梯**（试 → 验证 → 换策略重按）——提方案的那家自己撤回了：

- 它建立在「同一 buffer 的回车会被忽略」这个假设上，**[实测]** 说不会被忽略；
- 支持发送的只有 claude 和 qwen，qwen 不敲键盘、claude 单次写就成功 → **阶梯在当前全部
  生产路径上是死代码**；
- 而 **永不执行的代码比没有代码更糟**：不会被测试覆盖、随周边重构腐烂，而它第一次真正
  执行的时刻，恰好是「未知 CLI、未知版本、未知屏幕」——一段从没跑过的代码能遇到的
  最差条件。

保留下来的是它**验证**的那一半（和要不要重按正交）：更早更便宜的快信号通道、offset 窗口
内**计数**而不是首次命中即返回、把两种"不确定"拆开说、以证据取代版本钉子。

## 五、落地顺序（裁决）

1. **前台归属闸（`tpgid`）** ← 最前。理由：**唯一一道今天完全不存在、而且已经在漏的闸**；
   纯增量；而且是第 5 步的硬前置——正则今天是前台归属的意外代理，替代品没到位就动它
   是净损失。

   两条实现约束，都不能省：
   - **不要改 `cliForPid` 的语义、不要动 `session.cli`。** 它被 `ai-command-owner.ts:45,48,50`
     拿去和 `s.cli` / `b.cliId` 比对，vim 一起来就翻成 null 会把整条会话身份判成
     `identity_unconfirmed`。**新增**一个字段和一条 reason `foreground_not_cli`。
   - **必须是新鲜读数**，取在「最后观测 → 持久写入边界 → 真正写入」那个无 await 窗口里。
     **读不到 = 不写。** Windows 没有这个概念，单独给结论，不能默认放行。

2. 版本落库 + 信任账本（**只观测**，现有 key 先全标 verified 以保持现状不变）
3. 给 claude 补 `PermissionRequest` hook —— 见下面的安全陷阱
4. 闸门从屏幕切到事件；`claude-screen.ts` **降为探测器**（只保 `terminal_draft` 保护用户
   草稿，不再承担授权职责），并行跑一段看分歧率
5. 解版本钉子（`:49` 和 `:67` 两处一起）
6. 删 `claude-screen.ts`；codex 接原生通道

### 第 3 步自带一个安全陷阱

Claude 的 `PermissionRequest` 是一个**决策 hook**——它的 stdout 返回特定 JSON 可以
**直接替用户批准**。我们的 observer 绝不能往 stdout 写任何东西。

**核过了，今天是安全的**：`CLAUDE_OBSERVER_SCRIPT`（`claude-launch.ts:84+`）全程只往
socket 写，整体包在 `try{}catch{}` 里，所有拒绝路径都是静默 `process.exit(0)`；而且脚本
自己白名单了三个事件名，别的直接退出。

但 `claude-launch.ts:83` 那条注释「stdout belongs to Claude's hook result」现在是**礼貌**，
装上 `PermissionRequest` 之后就变成**安全关键**，措辞必须跟着升级。装它要改**两处**
（hooks.json 的数组 + 脚本里的白名单）。

## 六、仓库里已经有半套答案

`cli-adapters/src/index.ts:69-71` 的注释：

> 识别出的 CLI 图片粘贴自动插入；**verification 是元数据，不是确认闸门**。调用方仍然
> 校验连接身份，并且**不发回车**。

| | 图片粘贴 | 发消息 |
| --- | --- | --- |
| 带回车吗 | **不带** | 带 |
| 版本没验证过 | **照样粘，只打个标记** | **整个拒绝** |

**两套相反的策略并存在同一个仓库里，唯一的区别就是那个 `\r`。** 而且验证机制本身是死的：
三个调用方**没有一个传 `version`**，claude 的 `verifiedVersions` 还是空数组——图片粘贴在
生产里**永远走未验证路径**，跑了很久，没人抱怨。

顺带：`cli-adapters` 说 qwen 验证过 `0.21.14`，`ai-command-owner.ts:49` 要求 `0.23.1`
——同一个仓库里两个数字互相矛盾。**钉子已经漂移了，不是将来时。**

## 七、一个把可观测量变成受控量的机会

claude 启动时发三条查询：`CSI >0q`（XTVERSION）、`CSI ?u`（kitty 键盘协议）、`CSI c`（DA1）。
**现在是前端 xterm 在回答。** 如果哪天 xterm 开始回答 kitty 查询，claude 会切到 CSI-u 编码，
裸 `\r` 可能不再成立。

建议不是去观测这个，而是**把回答挪进 daemon，由 roost 确定性地答「不支持 kitty」**。

> 这不是观测，是**把一个可观测量变成一个受控量**——比观测它更值钱，因为一次性消灭了
> 整类漂移。

待验证：没有浏览器连着的会话里，这三条查询没人回答，claude 会怎么走？

## 八、一句话

这轮讨论想要的是「让那张表不失效」，实测之后的答案是：**那张表对我们几乎不存在，真正
缺的是一道从来没有过的闸——前台归属。** 而且它必须排在退掉读屏之前，否则我们会亲手
拆掉今天唯一挡着那个洞的东西。

## 九、第四路（釜底抽薪：能不能根本不敲键盘）的结论

### 9.1 为什么读屏和按回车绑死——最干净的一句表述

> **`\r` 是一个没有寻址的字节。它的含义完全由接收方当前的状态决定。而我们唯一能知道那个
> 状态的办法，就是看屏幕。**
>
> 所以读屏不是一个可以优化掉的实现细节——**它是「给无寻址字节补上寻址」的唯一手段**。
> 只要还按回车，读屏就退不掉；只要退了读屏，就不能按回车。

于是有且只有三个自洽的位置：

| | 读屏 | 自动回车 | 后果 |
| --- | --- | --- | --- |
| **P1** | 要 | 要 | **现状**。安全性挂在分类器上 → 版本钉子 → **[实测] 现在已经失效** |
| **P2** | 不要 | **不要** | 只插入正文、永不替用户按最后那一下。安全、无版本依赖、**对所有 CLI 成立** |
| **P3** | 不要 | 不要 | 走**有寻址**的原生通道。安全由协议保证 |

**P2 恰好就是 Warp 给自己的控制面定的规矩**（`specs/warp-control-cli/PRODUCT.md:9`：只提供
`input.insert` / `input.replace`，**永远不替你按回车**）。

而 Warp 自己的分界线很清楚：**它在自家 GUI 的输入框里按回车（那里它读得到自己的状态），
但在给外部程序的控制 API 里拒绝提供提交能力。谁看得见屏幕，谁才有资格按回车。**

roost 的位置更接近后者——后端独占 PTY，浏览器只发意图。`claude-screen.ts` 就是在硬造
「看得见屏幕」这个资格，而实测说明这个资格造不稳。

### 9.2 非键盘通道真正买到的是「有界性」，不是可靠性

所有原生通道（`thread/queue/add`、`/session/:id/message`、`--input-file`）都**明确指名了
收件人**，所以后果是**有界的**——它们**不可能**批准一次工具调用、不可能触发 OAuth。
而 `\r` 的后果是**无界的**，因为含义由屏幕决定。

**取证是代价，不是收益**：没有任何非键盘通道能给出 roost 现有 ledger 语义要求的逐字回执。
键盘在 roost 里的角色**不是投递手段，是取证手段**——它是唯一能让文本以 `user` 身份进入
原生 transcript 的办法。

### 9.3 「首条走 argv」只解决 2.7% [实测]

本机 `~/.roost/workspace.sqlite`（只读统计）：

```
6 条有消息的对话 / 222 条 user 消息
每条对话的 user 消息数：155, 36, 18, 10, 2, 1
首条占比 = 6/222 = 2.7%
```

**97.3% 的用户发言发生在一个已经存在的会话上。** 把首条搬到 argv/stdin，键盘问题一点
没动。这条路该做，但**要挂在「身份」这条线下面，不是「键盘」这条线下面**——它的收益是
可预测的转录路径，不是少敲键盘。

### 9.4 各 CLI 能不能从外面投进活着的 TUI

判据：**这个 CLI 的 TUI 是不是「它自己那个 server 的一个客户端」。**

| CLI | 能否 | 要不要我们启动 |
| --- | --- | --- |
| opencode | **能，零配置**（实测文字真的出现在输入框里） | 否（要 `lsof` 找端口） |
| codex | **能，但启动时不能带 `-c`** | 否（带 `-c` 就断，实践上要） |
| qwen | 能（跨会话协议自带 token 注册表，设计最干净） | 否（但默认关；**本机没装 qwen，此条未实测**） |
| grok | 能，但要显式开 `--leader` | 要 |
| **claude** | **只有 Channels，必须启动时开** | **要** |
| gemini / cursor-agent | **结构上不可能**，可钉死不再复查 | — |

**本机验证**：共享 daemon（`codex app-server --listen unix://`）确实在跑，而用户的 codex TUI
带着 `-c model_provider=…` → 已退化成内嵌，**按原样够不着**。

### 9.5 这一路对自己最狠的一刀

> 把「投递」从「要我们启动」放宽到「要么启动、要么能发现」，代价是多了一批**可被用户
> 启动参数悄悄掀掉**的失效条件——**这恰恰又是一类新的「按参数失效的经验表」，和你想
> 摆脱的那张表同源。**

**釜底抽薪没有消灭脆弱性，只是把「按版本失效」换成了「按启动参数失效」。** 那个带 `-c`
的 codex 就是活证据。而 claude——唯一天天在用的那个——对「用户自己起的会话」没有任何
外部接口，所以**对 claude，键盘这条路消不掉**。

### 9.6 两条顺手查实的现况

1. **claude 的 GUI 发送现在是死的，而且死了两重** [实测]：本机 2.1.273 撞上严格相等的
   2.1.266 钉子；`ROOST_CLAUDE_GUI_SEND` 也没设。`ai_commands` **0 行**。
   → **所以现在做 P2 不会退化任何正在工作的功能，止血的窗口期是免费的。**
2. **FIFO 是幻觉**：把 stdin 换成 FIFO 用户就没法打字了；做成「泵进程同时读 PTY 和 FIFO」
   ——**那就是 roost 今天在做的事**（daemon 独占 PTY 主端，`writeSession` 就是那个泵）。
   同样的字节、同样的 `\r`、同样无寻址。**写死在这里，免得以后再被提。** signal 同理排除。

### 9.7 落地顺序的修订

第四路把 **P2 提到了最前面**（它原本不在表里——在 OAuth 那条实测之前，这被当成可靠性
问题而不是安全问题）。与第二节那道前台闸合并后：

| # | 做什么 |
| --- | --- |
| **0** | **P2：把「只插入正文、不替用户按回车」做成一个可选模式。** 不依赖任何上游、对所有 CLI 成立、立刻能做、**现在做不退化任何在工作的东西** |
| **1** | **前台归属闸（`tpgid`）**——唯一一道今天完全不存在且已经在漏的闸 |
| 2 | codex 起私有 app-server socket，并先探一次共享 daemon |
| 3 | claude Channels：**先做一小时实验**，只回答「channel 事件在 transcript 里留不留可当回执的记录」 |
| 4+ | 版本落库/账本、给 claude 补 `PermissionRequest`、闸门切事件、解版本钉子、删读屏 |

### 9.8 明确不做

- **不要造统一的「非键盘投递层」**——九条通道的回执强度和失效模式互不相同，抽象会把最弱
  那条的语义强加给最强那条。
- **不要因为拿到了非键盘通道就顺手放宽「草稿优先」**——codex 原生队列是「空闲即执行」，
  和现在「草稿清空后执行」是两种产品行为。
- **不要试图靠「把分类器写得更全」同时保住读屏和回车**——失败模式不可撤销，而分类器的
  覆盖率永远是经验值。
- 邮箱 + mark-delivered：**不做**（转移到模型的自觉性，和 ledger 的确定性假设冲突）。
