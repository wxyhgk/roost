## 登录与读取重试修复

本地再次出现登录及数据接口超时。对运行中的网关采样，主线程停在 `uv__fsevents_close` / `uv_sem_wait`：大目录文件监听的原生关闭过程阻塞了 HTTP 事件循环。

- macOS 改为独立文件监听子进程；最后一个订阅退出时终止子进程，避免网关顺序关闭大量 FSEvents 句柄。
- 心跳看门狗处理子进程卡住或退出；失败通知当前订阅，回收旧进程后由客户端重连。Linux 仍使用原有有界监听实现。
- 仅重启本地网关，终端 owner PID 79026 与四个存活 PTY 的身份保持不变。
- 实际登录 HTTP 200，五次文件监听开关期间工作区请求最大 13 ms；摘要及详情数据均正常。
- 浏览器重新登录、刷新页面后不再出现读取重试；底栏有真实 CPU/内存/流量，终端 RTT 为 2–9 ms；订阅弹窗和新建菜单可打开。桌面宽度 1452 px 下无横向溢出。
- 新增隔离监听真实文件变化及子进程卡死测试。修复后的整个后端测试通过：262 项，255 通过、7 跳过；边界检查通过。

## FR 发布检查发现的问题

首次底栏候选版本未通过检查，因此没有切换线上版本：

- AI WebSocket 测试没有设置存活 runtime，较慢主机会触发后台离线事件，导致 cursor 从 1 变成 2。测试现显式提供匹配的存活 CLI，保留原快照与关闭断言。
- Linux 的 `utimes` 浮点换算可把整数毫秒保存为低一微秒的数值。旧的 `floor(mtime) + 1` 可能正好重复原时间戳，允许第二个编辑器用旧版本覆盖第一次保存。改为 `ceil(mtime) + 1` 并检查实际时间戳确实前进；不能前进时拒绝覆盖。现有并发 HTTP 测试继续要求一个 200 和一个 409，并增加成功版本递增断言。

AI 额度接入研究单独记录在 [接口调研](../../research/ai-subscription-apis.md)，此底栏版本只提供平台切换界面。
