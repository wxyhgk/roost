## 故障集成结果

新增 [peer-messages-resilience.test.ts](../../backend/tests/peer-messages-resilience.test.ts) 两项集成回归，由反方独立执行，2 项通过：

1. 忙碌/草稿期间不写入，真实 HTTP 网关关闭重建后仍保留同一排队消息；使用相同 requestId 重试仍为同一信封，恢复可写后只提交一次。
2. 网关离线期间，迟到的接收证据由仍存活的 owner 持久保存；重建后旧 epoch 的 cursor 要求重新取快照，新快照包含 accepted，后续 WS 变化继续同步且不重复投递。

HTTP、WebSocket、SQLite 连接、peer coordinator 和 command owner 使用实际实现；CLI runtime、屏幕、hook 和原生 JSONL 回执由夹具模拟。因此证明的是实际后端重建及投递约束，不是第二次真实模型或浏览器断网试验。
