# Roost

**中文** · [English](README.en.md)

**在浏览器里管理 shell 会话的本机工作台。关掉标签页，里面跑着的东西也不会停。**

![Roost 的三栏界面：左侧会话列表、中间终端、右侧文件树](docs/roost.png)

`tmux` 能让会话活下来，但它不知道终端里跑的是什么；网页终端方便，但会话跟着页面一起死。
Roost 两样都要——下面这些场景是它实际在解决的事。

## 一条设计原则：别抢终端的地方

**终端是主角，别的东西一律不常驻。**

文件预览和编辑是**浮窗**——能拖能缩，可以钉住让它一直浮着，看完就关。它盖在终端上面，
**不把终端挤窄**。右侧面板（文件树、笔记、系统信息、进程）也是召之即来的：从图标栏点开，
不用就收起。

这不只是好看。终端一被挤窄，里面的全屏 TUI 就得整屏重排；而宽度一变，**之前那些按旧宽度
产出的输出会被重新折行**，表格错位、光标重绘落在半帧上。所以在 Roost 里，看一眼文件、
记一条笔记、查一下端口，都不会动到你正在盯的那块画面。

---

### 「AI 在跑，我想去干点别的」

跑一个 AI CLI 可能要二十分钟，而你恰恰需要在这二十分钟里离开。

PTY 由独立进程持有，**关掉标签页、重启后端、断网十分钟都不打断它**。侧边栏实时显示
每个会话"在干活 / 干完了 / **在等你批准**"，安静下来发浏览器通知，标签页标题带未读数。

这些状态来自 CLI 自己的 hook 和协议，**不是读屏幕猜的**——所以它不会把一个正在刷屏的
进度条误判成"还在工作"，也不会漏掉一个已经停下来等你点头的确认框。

### 「换一台设备接着看」

同一个会话可以同时开多个窗口，**每个窗口从自己已经看完的位置继续收输出**，不重放、
不丢中间段。公司的 Mac 上开着，回家用另一台打开，两边互不干扰。

窗口之间尺寸不一样也不打架：守护进程把尺寸变化按流序插进输出里，客户端据此在**正确的
字节位置**重排，所以改宽度不会把之前的输出重新折断。

### 「网很慢，打字跟不上」

跨太平洋的链路往返两三百毫秒，每敲一个字都要等一个来回。

Roost 做**本地回显预测**：按键先画在屏幕上，真回显到了再对账，对不上就撤销。它是一层
覆盖，不进解析器、不进网络，最坏的情况只是白画一帧。**在全屏 TUI 里同样有效**——而这
恰恰是同类方案通常失效的地方。状态栏有延迟读数，并且会标注这个读数有多旧。

### 「终端里刚出来的东西，我想留下」

选中一段输出，**存笔记**或**存片段**。笔记跟着会话走，片段进片段库。
每个会话还有完整归档，可以分页翻、全文搜、整段下载。

### 「给 CLI 一张图 / 一个路径」

截图直接粘进终端，按各家 CLI 自己的规则插入。文件树里把文件**拖进终端就变成路径**。
文件树支持树形和列表两种浏览、服务端一次遍历的快速搜索、上传下载、右键菜单。

点开预览能看代码、图片、PDF、Markdown 和 3D 分子；编辑是原子写回的，并且会检测
文件在外面被改过。弹窗能拖能缩，也可以钉成悬浮窗一边看一边敲。

### 「这台机器现在到底怎么样」

内置系统面板，不用另开一个监控工具：CPU（用户态 / 系统态 / 空闲、频率、缓存、插槽）、
内存（活跃 / 缓存 / 待写入 / 回写中）、磁盘读写速率与累计量、网络连接数、
**监听端口和 UDP 绑定**、进程状态分布（运行 / 休眠 / 阻塞 / 僵尸）、高占用进程、
GPU、内核与时区、以及你关注的那几个服务在不在。

还能看**这个终端自己起了什么服务、占了哪个端口**——判据是控制终端，不是父子关系，
所以进程被过继出去也跟得住。

### 「顺手画个分子」

`.mol` / `.sdf` 直接在浏览器里画，画完送进终端。

---

AI 能力不由 Roost 提供，来自你自己跑的 CLI。目前认识
**Claude Code / Codex / Gemini CLI / OpenCode / Qwen Code / Grok / Oh My Pi**。
界面中英双语。

## 跑起来

需要 **Node.js ≥ 22.13.0**（下限由 `node:sqlite` 划的）。

```sh
npm ci        # 首次，项目根目录
npm start     # 打开 http://localhost:5173
cat ~/.roost/auth-password   # 首次启动生成的随机密码
```

## 安全边界

不是托管服务，没有多租户和权限模型。认证只有一道：本地生成的随机密码，写在
`~/.roost/auth-password`（0600）。

**它挡的是同一网络里的其他人，不是为公网暴露设计的。** 登进来的人能在你机器上执行
任意命令。要放公网，请在反向代理那层再加一道。

纯 HTTP 访问要显式放行 `ROOST_AUTH_INSECURE_HTTP=1`；跨来源用 `ROOST_ALLOWED_ORIGINS`。

## 装成系统服务

`npm start` 是开发入口——关掉它终端就停了。要让它一直在：

```sh
npm ci && npm run build --workspace frontend
brew install caddy
npm run service:install     # 入口 http://localhost:8080
```

`npm run service:status` 看状态，`service:uninstall` 卸载（不动数据），
`node scripts/install-service.mjs --dry-run` 只打印不动系统。

**装三个服务而不是一个**，因为 PTY 必须活在一个不会因为改代码而重启的进程里：

| 服务 | 跑什么 |
| --- | --- |
| `com.roost.terminal` | PTY 都在这个进程里 |
| `com.roost.backend` | 等 owner 就绪后起 HTTP 后端 |
| `com.roost.web` | 静态资源 + 反代 `/api` |

`backend` 和 `web` 随便重启，终端不受影响；**重启 `terminal` 会结束所有会话**。
日志在 `~/.roost/logs/`。

Linux 用 systemd 同理。群晖 NAS 见 [`deploy/README.md`](deploy/README.md)。
改完前端发布：`npm run build --workspace frontend && npm run publish`（资产先、外壳后，
反过来会白屏）。

## 要知道的几件事

- **守护进程退出或机器重启，运行中的任务不能恢复**，其余情况（刷新、断网、后端重启、
  后端崩溃）都能。`npm run daemon:status` / `daemon:stop` 管它。
- **Hide** 只是隐藏，进程还在；**Kill** 才终止并删记录。Shell 退出后的"重新启动终端"
  是新进程，保存的画面不代表原来的程序还活着。
- 历史有容量上限，超出时优先保留近期内容并在页面上提示；归档默认上限 256 MiB。
- 数据默认在 `~/.roost/workspace.sqlite`，`ROOST_DATA_DIR` 可换目录。

## 开发

```sh
npm run dev      # 后端改动自动重载，PTY 保持运行（和 npm start 同端口，别同时开）
npm run verify   # 类型检查 + 测试 + 前端构建 + 依赖边界检查
```

改了守护进程或运行时的源码，**要停掉守护进程再启动才生效，这会结束已有终端**。

包在 `packages/`（协议、运行时、守护进程、存储、附件、CLI 适配），应用在 `backend/`
和 `frontend/`。包之间只走公开入口，`verify` 会检查。
详见 [终端守护进程说明](packages/terminal-daemon/README.md)。

## 站在谁的肩膀上

Roost 里不少东西是从别的项目学来的。`research/` 里一份一份记着**读了什么源码、
学到哪一条、以及哪些看完决定不抄**。

**学来的：**

- **[tty7](https://github.com/l0ng-ai/tty7)**（同类的终端工作台，Rust）——「尺寸回声」
  和「重放按录制时的几何分段」两条都是从它的源码学的。核心洞见是：resize 必须在**字节流
  里**同步，不是「同时发出」；否则已经在路上的旧宽度字节会被按新宽度解析。
- **Warp** —— 「少猜，多让对方告诉你」。把 AI 状态从读屏幕改成读 CLI 自己的 hook 和协议，
  这个方向是从它那里确认的。
- **mosh** —— 同步「屏幕现在长什么样」而不是追字节流。我们的重放用服务端网格重新序列化
  出当前画面，是同一个思想。
- **tmux** —— 客户端／服务端分离，以及「为最慢的观众降速是在惩罚所有人」：它在 2009、
  2015、2016 三次实现「因客户端慢而限制生产者」，三次都删掉了。我们因此选择丢帧而不是
  暂停 PTY。
- **xterm.js**、**node-pty**、**Ketcher** 等等,构成了终端、PTY 和分子编辑的底座。

**看完决定不抄的**也记了，因为理由比结论有用：tty7 的本地行编辑器（生效条件太窄，
在 agent TUI 里等于不存在）、systemd／launchd 的 socket activation（只保监听 socket，
不保进程，对我们正交）、`process.execve` 热交接（失败全是静默的，见
[`research/daemon-handoff-findings.md`](research/daemon-handoff-findings.md)）。

**我们自己往前走的几步：**

- **本地回显预测在全屏 TUI 里也有效。** 同类方案通常要靠 shell 提示符标记才敢接管，
  于是在 vim、htop 和所有 agent TUI 里完全失效——而那恰恰是我们的主场景。我们的做法是
  一层覆盖：不进解析器、不进网络、对不上就撤销，最坏是白画一帧。
- **延迟读数测在承载按键的那条链路上**，并且显式建模「这个读数有多旧」。测在另一条
  通道上的延迟，和你打字时感受到的延迟不是同一个数。
- **重放的是重新序列化出的当前画面，不是原始历史。** 这让一整类「模式补偿」的 bug
  对我们不存在——备用屏状态由快照自带，不需要靠 fold 去补。
- **替 agent 按回车时等回显，不等固定时间。** 别人睡 200 毫秒赌它到了；我们等到在屏幕上
  看见自己那段正文再按——等证据，不等时间。
- **每个 PTY 一个私有的 app-server socket。** 官方文档说第三方观察者没法确定 TUI 和
  会话的对应关系；而一条 socket 上只有一个 TUI，归属就不用猜了。
