# Roost

在浏览器里管理 shell 会话的本机工作台。

会话不住在网页里，住在一个独立的守护进程里。关掉标签页、重启 HTTP 后端、断网重连，
里面跑着的东西都不会被打断——Roost 就是它们飞回来歇着的那根横木。

AI 能力**不由 Roost 提供**，来自你在终端里跑的 CLI。Roost 做的是把它们放进一个能
随时回来的地方，认得出是哪一个在跑，并在旁边配上文件树、预览、笔记和会话状态。
目前认识 Claude Code、Codex、Gemini CLI、OpenCode、Qwen Code、Grok 和 Oh My Pi。

![Roost 的三栏界面：左侧会话列表、中间终端、右侧文件树](docs/roost.png)

## 它是什么，不是什么

**是**给一个人、一台机器用的工具。所有数据在本地 SQLite，所有进程在本机。

**不是**托管服务或云 IDE。没有多租户、组织、权限模型。认证只有一道：一个本地生成的
密码，用来挡住同一网络里的其他人，不是为公网暴露设计的。

## 能做什么

- **会话不随页面走。** PTY 由独立守护进程持有，刷新、断线、后端重启后从你已经看完的
  位置继续收输出，不重放、不丢中间段。
- **认得出终端里在跑什么。** 识别常见的 AI CLI，读它们的会话记录，在侧边栏显示状态，
  并按各自的规则往里插入图片。
- **文件树**：树形 / 列表两种浏览，服务端一次遍历的快速搜索，上传下载，右键菜单，
  拖到终端变路径。
- **预览与编辑**：CodeMirror + Shiki 高亮，图片 / PDF / Markdown 插件式渲染，
  原子写回并做 mtime 冲突检测。弹窗可拖动缩放，可钉住变悬浮窗。
- **笔记与片段**：随会话走的本地笔记，代码片段库。
- **分子编辑器**：`.mol` / `.sdf` 走 Ketcher，画完可以直接送进终端。
- **服务监控**：systemd 服务状态、CPU、内存、运行时长。
- 中英双语界面。

## 安装与日常运行

需要 Node.js **v25 或 v26**（后端用 `node:sqlite`，测试用实验性的模块 mock）。
v25.9.0 全绿；v26.8.2 上除了 `backend/tests/watcher-boundaries.test.ts` 之外全绿——那一个用例依赖 `mock.module`，Node 26 改掉了它，是测试的问题不是运行时的问题。

首次在项目根目录安装所有依赖（npm workspaces，共用一个锁文件）：

```sh
npm ci
```

日常使用：

```sh
npm start
```

打开 <http://localhost:5173>。后端默认监听 `127.0.0.1:8787`。

此入口让 HTTP 后端以非 watch 模式运行，前端使用 Vite 开发服务器。后端启动时自动连接或启动独立终端守护进程；结束前后端不会结束守护进程中的 Shell。任一网页服务退出会结束另一网页服务，避免留下半启动状态。

开发后端、希望修改后立即重载时使用：

```sh
npm run dev
```

`dev` 的 HTTP 后端自动重载后会重新连接同一个终端守护进程，PTY 保持运行。两个入口使用相同端口，不要同时启动。首次从旧版进程内 PTY 升级时，旧 Shell 无法转移给守护进程，应先完成正在运行的任务，再重启后端并重新启动终端。

## 访问与认证

首次启动时自动生成一个 32 字节的随机密码，写进 `~/.roost/auth-password`（权限 0600，
只有你自己能读）。想看就 `cat` 它，界面里也能改。

```sh
cat ~/.roost/auth-password
```

默认要求 secure cookie，也就是假定你走 HTTPS。纯 HTTP 访问（比如本机直连或内网 IP）
需要显式放行：

```sh
ROOST_AUTH_INSECURE_HTTP=1 npm start
```

**这道认证挡的是同一网络里的其他人，不是为公网暴露设计的。** 登进来的人能读写工作
目录下的文件、能往终端里发输入——也就是能在你机器上执行任意命令。要放到公网，请在
反向代理那一层再加一道访问控制，别只靠它。

跨来源访问用 `ROOST_ALLOWED_ORIGINS` 声明，逗号分隔。

## 会话与数据

- 刷新网页或短暂断线：后端中的 Shell 仍在时可重连。
- Hide session：隐藏会话，保留后台进程；Reopen 重新连接。
- Kill session：终止进程并删除会话记录。
- Shell exited 后的“重新启动终端”：沿用会话和目录启动新 Shell。保存的画面不代表原来的程序仍在运行。
- HTTP 后端退出、重启或崩溃：独立守护进程中的任务继续运行，网页恢复连接后补收输出。
- 守护进程退出或机器重启：原来的运行任务不能恢复，需启动新 Shell。
- `npm run daemon:status` 查看守护进程；`npm run daemon:stop` 主动停止守护进程及其所有终端。

默认数据位于 `~/.roost/workspace.sqlite`。设置 `ROOST_DATA_DIR` 可使用独立数据目录，适用于隔离测试；不会迁移默认目录的数据。后端也支持 `HOST`、`PORT`；如果更改后端端口，需要相应调整 `frontend/vite.config.ts` 中的代理目标。

## 终端恢复

刷新、断线或 HTTP 后端重启时，每个窗口从自己已经显示完整的位置继续接收输出。守护进程保留 PID、实例 ID 和输出游标。真正启动新 Shell 时才产生新实例标识。历史画面和它之后的输出一起保存，两个窗口可分别恢复。

HTTP 后端的退出只断开连接；守护进程持续收集和保存输出。守护进程收到 `SIGINT` / `SIGTERM` 时保存历史并结束 PTY。强制杀掉守护进程或断电仍可能丢失尚未落盘的内容；运行中按约 1.5 秒批次写入。

历史保留有容量限制：每个会话最多保留约 2,000,000 个 UTF-16 代码单元的原始输出及 16,384 个输出片段；落盘的历史画面与增量合计上限为 512,000 个代码单元。超出范围时优先保留近期内容，页面会提示历史可能不完整。快照本身不会被截成半段终端控制序列。另有按会话追加的完整归档（默认上限 256 MiB），可通过终端栏的历史记录按钮分页查看、搜索与下载；删除会话会连带删除其归档。

旧数据库会自动增加恢复元数据列。旧记录缺少精确快照边界时，优先恢复最近的原始输出，并提示历史可能不完整。更新前已经打开的页面请刷新一次，使用新的恢复协议。

## 验证

```sh
npm run verify
```

依次执行所有包与应用的类型检查、测试、前端生产构建和包依赖边界检查；任一步失败即返回非零退出码。回归测试使用临时文件或 mock 数据，不读取用户的工作区数据库，也不向运行中的服务发送测试消息。

单独运行后端测试：

```sh
npm test --prefix backend
```

安装时会自动修复 macOS 预编译 PTY 辅助程序的执行权限。如果安装后的原生 PTY 模块仍无法加载，可尝试 `npm run rebuild-pty --prefix backend`（需要本机编译工具链）。

## 代码如何组织

私有本地包与前后端一起安装、一起发布当前应用，不需要发布到 npm。

| 位置 | 负责什么 | 对使用者的意义 |
| --- | --- | --- |
| `packages/terminal-protocol` | 前后端共同的终端消息、版本和校验 | 更新连接或恢复规则时，双方使用同一份约定，减少连接成功却不能输入的问题 |
| `packages/terminal-runtime` | Shell 进程、输入输出、历史恢复与资源释放 | 修复重连、输出重复或终端退出问题时，可以集中验证，不牵动项目列表和文件预览 |
| `packages/workspace-store` | 项目、会话及终端历史的 SQLite 存储 | 调整保存方式时，能独立验证旧数据兼容，减少更新后记录丢失的风险 |
| `packages/terminal-daemon` | 独立终端进程、本机 socket 和客户端 | HTTP 后端重启时保留正在运行的 CLI |
| `packages/attachment-store` | 图片接收、校验、占用统计和主动清理 | 查看图片占用并清理不再使用的附件 |
| `packages/cli-adapters` | CLI 识别与图片插入规则 | 不同 CLI 共用上传流程，保留必要的兼容处理 |
| `backend/src` | 启动配置、HTTP/WebSocket 接口、文件预览，以及组装这些包 | 页面操作仍有统一入口，应用层只负责把请求交给对应能力 |
| `frontend/src` | 界面和浏览器终端 | 界面调整与 Shell 的运行逻辑分开维护 |

终端运行时由独立守护进程持有；HTTP 后端通过本机 socket 连接。同一数据目录复用同一个守护进程，隔离数据目录使用独立实例。详见 [终端守护进程说明](packages/terminal-daemon/README.md)。

包通过公开入口导入，禁止跨目录读取另一个包内部文件。协议包保持浏览器可用；存储和运行时通过工厂创建，每个实例持有自己的资源，单纯导入不会打开数据库或启动 Shell。HTTP 后端关闭时断开守护进程连接并关闭自己的数据库连接。

例如只验证终端能力：

```sh
npm test --workspace @roost/terminal-runtime
npm run typecheck --workspace @roost/terminal-runtime
```

修改 HTTP 后端包源码后，日常 `npm start` 模式需重启后端；`npm run dev` 会自动重载。修改终端守护进程或运行时源码后，需要主动停止守护进程再启动后端才会生效，这会结束已有终端。包直接提供 TypeScript 源码，由应用工具链加载。

附件管理接口见 [ATTACHMENTS_API.md](backend/ATTACHMENTS_API.md)：支持全局统计、按会话列出附件和逐个删除；管理界面由前端后续接入。

## 部署

`npm start` 是开发入口。要让它常驻，需要三样东西各跑各的：持有 PTY 的
`deploy/terminal-owner.mts`、HTTP 后端 `backend/src/index.ts`，以及前面挡着的反向
代理（提供 `frontend/dist`、反代 `/api` 含 WebSocket）。用 launchd 还是 systemd
随意。容器方案见 [`deploy/README.md`](deploy/README.md)。

发布静态资源用 `deploy/publish-assets.mjs` 而不是 `cp`：哈希资源只增不删，旧页面
还在加载的懒加载块不能被覆盖，它会检查同名不同内容并拒绝。
